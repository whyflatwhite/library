# Развертывание library в Linux (ЛР2)

Приложение развернуто без контейнеров на двух виртуальных машинах
Debian 12 (без графического интерфейса) в VMware Workstation.

## Схема

| Машина       | IP (host-only, VMnet1) | IP (NAT, VMnet8) | Что на ней                                   |
|--------------|------------------------|------------------|----------------------------------------------|
| library-app  | 192.168.56.10          | 192.168.64.129   | Python, приложение, systemd-служба `library` |
| library-db   | 192.168.56.11          | 192.168.64.131   | PostgreSQL                                   |
| Windows-хост | 192.168.56.1           | 192.168.64.1     | посторонний узел для проверки недоступности БД |

Первый адаптер каждой ВМ (NAT, VMnet8) дает интернет, второй (Host-only,
VMnet1) – сеть между ВМ и хостом. NAT-адреса выдает DHCP и могут меняться.

Удаленный доступ для участников на других компьютерах: проброс портов
VMnet8 на компьютере хоста (`2222` -> library-app:22, `2223` ->
library-db:22) и Tailscale.

## Порядок развертывания

1. **Сеть и ВМ** (Лера): две ВМ, постоянные адреса в `/etc/network/interfaces`,
   `apt update && apt upgrade`, пакеты `ufw curl git`.
2. **Пользователи и SSH-ключи** (Лера): администраторы `lera`, `yulya`, `ira`
   на обеих ВМ; пользователь `libapp` (без входа, без домашней папки) только
   на library-app; публичные ключи в `~/.ssh/authorized_keys`
   (права 700 и 600).
3. **Проверка входа по ключу** со всех трех компьютеров.
4. **Усиление SSH** (Лера): `bash deploy/harden.sh` на обеих ВМ.
5. **Сервер БД** (Юля): `OWNER_PASSWORD=... APP_PASSWORD=... bash deploy/db-setup.sh`.
6. **Сервер приложения** (Ира): на library-app создать deploy key и добавить
   его в GitHub (Settings -> Deploy keys, только чтение), затем
   `bash deploy/app-setup.sh`. При первом запуске скрипт создаст
   `/etc/library/library.env` и `migrate.env` из шаблонов и остановится –
   вписать пароли ролей БД вместо `CHANGE_ME` и запустить скрипт снова.
   Скрипт сам выполнит миграции и запустит службу.
7. **Firewall** (Лера): `bash deploy/firewall.sh app` на library-app,
   `bash deploy/firewall.sh db` на library-db.
8. **Проверка**: перезагрузка обеих ВМ, `curl http://192.168.56.10:8000/health`,
   недоступность БД с хоста.

## Требования

- Приложение не запускается от root – работает под пользователем `libapp`.
- Открыты только нужные порты: library-app – 22 (из 192.168.56.0/24 и сети
  Tailscale 100.64.0.0/10), 8000; library-db – 22 (из тех же сетей),
  5432 (только с 192.168.56.10).
- Пароли и env-файлы в репозитории не хранятся; настройки лежат в
  `/etc/library/library.env` и `/etc/library/migrate.env` (права 640).
  В репозитории только шаблоны `deploy/*.env.example` с `CHANGE_ME`.
- Вход root по SSH запрещен, вход по паролю запрещен, разрешены только
  `lera`, `yulya`, `ira`.
- Код доступен приложению только для чтения.
- Доступ к БД: две роли PostgreSQL – `library_owner` (миграции) и
  `library_app` (чтение/запись данных), обе без прав суперпользователя;
  подключение разрешено только с 192.168.56.10 (`pg_hba.conf`,
  `listen_addresses`).

## Проверки

| Что проверить                | Команда                                                         | Ожидаемый результат      |
|------------------------------|-----------------------------------------------------------------|--------------------------|
| root и пароль запрещены      | `sudo sshd -T \| grep -E "permitrootlogin\|passwordauthentication"` | `no` и `no`          |
| Приложение не от root        | `ps -o user,pid,cmd -C uvicorn`                                 | пользователь `libapp`    |
| Права на конфиг              | `sudo ls -l /etc/library/`                                      | `640`                    |
| Firewall                     | `sudo ufw status verbose`                                       | только нужные порты      |
| БД недоступна с хоста        | PowerShell: `Test-NetConnection 192.168.56.11 -Port 5432`       | `False`                  |
| БД доступна с library-app    | `nc -zv 192.168.56.11 5432`                                     | порт открыт              |
| Приложение отвечает          | `curl http://192.168.56.10:8000/health`                         | успешный ответ           |
| Паролей нет в истории git   | `git log --all --full-history -- .env`                          | пусто                    |
